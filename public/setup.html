架一份只屬於你的 Mothership

Mothership 是一個像 Trello 的看板 App：卡片、清單、行事曆、時間軸、年度回顧，手機、iPad、電腦登入同一個帳號就會即時同步。照著這份教學做，你就會有一份完全屬於自己的 Mothership。不用會寫程式，也不用會 GitHub。

  • ⏱ 大約 30 分鐘
  • 💰 全部免費
  • 💻 建議用電腦設定
  • 🔒 資料只有你看得到

先搞懂：我們要做什麼？

把整件事想成「開一間自己的店」：

📦 GitHub＝倉庫放 Mothership「程式碼」的地方。你會從原作者的倉庫複製一份到自己名下（這個動作叫 Fork）。
🏪 GitHub Pages＝店面GitHub 附送的免費網站空間。你的倉庫會自動變成一個網址，任何裝置打開就能用（這叫部署）。
🗄 Supabase＝保險櫃存你的看板資料、管理登入帳號的地方。每台裝置登入同一個帳號，看到的就是同一份資料。
🤖 Claude＝助理（選用）想加功能、改樣子時，可以用中文請它幫你改。完全不用也能正常使用。
做完之後你的 Mothership 和原作者的是兩份完全分開的 App：網址不同、資料庫不同。你看不到他的看板，他也看不到你的。
開始前準備好
  • 一個常用的 Email（會收到驗證信）
  • 一台電腦（用 iPad 也可以，只是按鈕比較難找）
  • 一個密碼管理器或記事本，用來記幾組密碼

1. 申請 GitHub 帳號 約 5 分鐘

已經有 GitHub 帳號的話，登入後直接跳到第 2 步。

1

打開 github.com/signup。

2

依序填入 Email、密碼、使用者名稱，按 Continue 或 Create account。

使用者名稱會變成你的網址例如取 amy-notes，你的 Mothership 網址就會是 https://amy-notes.github.io/program_manager/。只能用英文、數字和減號。
3

可能會要你做一個小驗證（選圖片之類），證明你不是機器人。

4

去信箱收 GitHub 寄來的驗證碼，填回網頁。

5

如果問你一些問卷問題，可以按 Skip personalization 跳過。方案選免費（Free）。

✅ 完成的樣子畫面右上角有你的頭像圓圈。現在可以回到這頁最上面，填你的使用者名稱。

2. 複製一份 Mothership 給自己（Fork） 約 2 分鐘

1

確定已經登入 GitHub，打開原作者的倉庫：

https://github.com/antony910911/program_manager
2

在頁面右上方找到 Fork 按鈕（旁邊有一個分岔的小圖示），按下去。

用手機找不到？手機版畫面比較擠，可以把網頁往右滑，或改用電腦。
3

會出現「Create a new fork」頁面。什麼都不用改，Repository name 保持 program_manager（改了的話，下面的網址也要跟著改），直接按最下面綠色的 Create fork。

✅ 完成的樣子網址變成 github.com/你的使用者名稱/program_manager，標題下面有一行小字「forked from antony910911/program_manager」。這就是你自己的倉庫了。

3. 打開自動部署和網站功能 約 3 分鐘

複製來的倉庫，GitHub 為了安全會先把「自動部署」關起來，要你自己按一下打開。

3-1 打開自動部署（Actions）

1

在你的倉庫頁面上方，點 Actions 分頁。或直接打開：
github.com/你的使用者名稱/program_manager/actions

2

會看到一段說明「Workflows aren't being run on this forked repository」，按綠色的 I understand my workflows, go ahead and enable them。

3-2 打開網站功能（Pages）

1

點倉庫上方的 Settings（齒輪），左邊選單點 Pages。或直接打開：
github.com/你的使用者名稱/program_manager/settings/pages

手機上找不到 Settings？它可能藏在倉庫上方分頁列的最右邊，或「⋯」選單裡。直接打開上面的連結最快。
2

找到 Build and deployment 底下的 Source，下拉選單選 GitHub Actions。選了就會自動儲存。

✅ 完成的樣子Source 那格顯示 GitHub Actions。網站還不會馬上出現，要等第 7 步填好資料庫之後才部署。

4. 申請 Supabase、建立資料庫 約 5 分鐘

1

打開 supabase.com，按 Continue with GitHub，用剛剛的 GitHub 帳號登入，按 Authorize 同意。

2

第一次會要你建立一個「組織」（Organization）：名稱隨便填（例如你的名字），Type 選 Personal，Plan 選 Free，按 Create organization。

3

接著建立專案（New project），填這幾格：

  • Project name：隨意，例如 mothership。
  • Database Password：按 Generate a password 自動產生，複製起來記在密碼管理器（之後幾乎用不到，但最好留著）。
  • Region（主機放在哪）：選 Northeast Asia (Tokyo)。離台灣近，存檔比較快。

按 Create new project。

4

等 1～2 分鐘，畫面會從「Setting up project」變成專案首頁。

✅ 完成的樣子左邊有一排小圖示的選單（Table Editor、SQL Editor、Authentication…）。

5. 建立資料表 約 3 分鐘

這一步是告訴資料庫「要怎麼存看板」，以及「每個人只能看自己的資料」。你只要複製、貼上、按執行。

1

在 Supabase 左邊選單點 SQL Editor（一個 >_ 的圖示），按 + New query（或 New SQL snippet）。

2

按下面的 複製，把整段貼進 Supabase 的大輸入框（先把裡面原本的字刪掉）：

讀取中…

這段來自你倉庫裡的 supabase/schema.sql。

3

按右下角的 Run（或鍵盤 Ctrl＋Enter，Mac 是 ⌘＋Enter）。

跳出「Potential issue detected」或「destructive operation」的警告？這是正常的，因為這段會先清掉舊的設定再建立。按 Run this query 繼續。
✅ 完成的樣子下方結果顯示 Success. No rows returned。

6. 設定登入 約 2 分鐘

1

左邊選單點 Authentication，再點 URL Configuration。

  1. Site URL 改成你的網址，按 Save：
    https://你的使用者名稱.github.io/program_manager/
  2. Redirect URLs 按 Add URL，貼上同一個網址，按 Save URLs。

之後點確認信、或用「Email 連結」登入時，才會回到你的網站。

2

建議做：關掉「註冊要收確認信」，註冊完就能直接登入。

  1. 一樣在 Authentication 裡，點 Sign In / Providers（舊介面叫 Providers）。
  2. 點 Email，把 Confirm email 的開關關掉，按 Save。
為什麼建議關掉？Supabase 免費版內建的寄信功能每小時只能寄幾封，常常收不到確認信。只有你自己（或少數朋友）用的話，關掉比較省事。

7. 把資料庫接到你的網站 約 5 分鐘

⚠️ 這一步最重要，一定要做你複製來的程式裡，預設接的是原作者的資料庫。沒做這一步的話，你的網站會把資料存到別人那裡。

7-1 從 Supabase 複製兩個值

1

在 Supabase 專案頁面最上方按 Connect；或左下角齒輪 Project Settings › Data API 和 API Keys。

2

找到這兩個值，先複製到記事本：

  • Project URL：長得像 https://abcdefghijkl.supabase.co
  • Publishable key（sb_publishable_ 開頭）；如果只看到 anon public（eyJ 開頭的一長串），用它也可以。
只複製「公開」的那把這兩個值本來就會放進網站裡，給別人看到沒關係。但不要複製 secret 或 service_role 那把，那把等於資料庫的萬能鑰匙。

7-2 填進 GitHub

1

回到你的 GitHub 倉庫，點 Settings › 左邊 Secrets and variables › Actions。或直接打開：
github.com/你的使用者名稱/program_manager/settings/variables/actions

2

確認上方選的是 Variables 分頁（不是 Secrets），按綠色的 New repository variable。

3

第一個：Name 完全照抄（大小寫、底線都要一樣），Value 貼上 Project URL，按 Add variable。

VITE_SUPABASE_URL
4

再按一次 New repository variable。第二個：Name 照抄，Value 貼上 Publishable key（或 anon key），按 Add variable。

VITE_SUPABASE_ANON_KEY
✅ 完成的樣子Variables 分頁裡有兩行：VITE_SUPABASE_URL 和 VITE_SUPABASE_ANON_KEY。
為什麼不直接改程式碼？填在 Variables 裡，之後更新到原作者的新版時（第 11 步）不會被蓋掉，也不會跟新版衝突。

8. 網站上線、註冊帳號 約 5 分鐘

1

點倉庫上方的 Actions，左邊點 Deploy to GitHub Pages。

2

右邊會有一個 Run workflow 按鈕，按下去，再按跳出來的綠色 Run workflow。

3

等 1～3 分鐘（可以重新整理頁面看進度），出現綠色勾勾 ✅ 就部署好了。

4

打開你的網址：

https://你的使用者名稱.github.io/program_manager/

切到 註冊 分頁，輸入 Email 和密碼（至少 6 個字），建立帳號。

5

檢查有沒有接對資料庫：回到 Supabase，左邊點 Authentication › Users。

✅ 接對了這裡看得到你剛剛註冊的 Email。
❌ 看不到你的 Email？代表網站還接在原作者的資料庫。回到第 7 步，檢查兩個 Variable 的名稱有沒有打錯、是不是放在 Variables（不是 Secrets），改好後再做一次這一步的 1～3。

9. 裝到手機、iPad、電腦 每台約 1 分鐘

iPhone／iPad

1

用 Safari 打開你的網址，用同一組 Email／密碼在 登入 分頁登入。

2

按分享按鈕（方框加一個向上箭頭），往下滑選 加入主畫面，再按 新增。之後從主畫面的圖示打開，就像一般 App。

Android

用 Chrome 打開網址並登入，按右上角 ⋮ › 加到主畫面（或「安裝應用程式」）。

電腦

用 Chrome、Edge 或 Safari 打開網址並登入。想要獨立視窗：Chrome／Edge 網址列右邊有一個「安裝」小圖示。

✅ 完成的樣子在手機新增一張卡片，幾秒內電腦上也會出現。
忘記密碼？在登入畫面選「Email 連結」，收信點連結就能登入（第 6 步的網址要設定正確）。

1

回到 Supabase 的 SQL Editor › + New query，把下面這段貼上、按 Run（一樣可能跳警告，按 Run this query）：

讀取中…
2

打開你的 Mothership › 右上角 設定 › Beamup › 產生連接碼 › 複製連接碼。

3

手機打開 Beamup（一樣可以加入主畫面）：

https://thought-task-entry.antony910912.workers.dev

右上角齒輪 設定 › 「待辦事項 → 專案管理工具」，把連接碼貼進第一格，按 測試連線。

✅ 完成的樣子在 Beamup 打一個待辦送出，幾秒內出現在 Mothership 雙層模式上方的「待辦」清單，卡片上有綠色的 Beamup 標記。
🔑 連接碼不要給別人拿到連接碼的人可以送東西進你的看板。不小心外流就到 Mothership 的 設定 › Beamup 按「換一組」。
行事曆同步（Google／Outlook／iCloud）這個比較進階，需要額外設定 GitHub 和 Supabase 的金鑰。想要的話，照倉庫裡的 DEPLOY.md「連接行事曆」做，或請 Claude 帶你做（第 12 步）。

11. 之後怎麼更新到新版 約 2 分鐘

原作者之後加了新功能，你的 Mothership 不會自動跟著更新（因為是你自己的一份）。想更新的時候：

1

登入 GitHub，打開你自己的倉庫 github.com/你的使用者名稱/program_manager。

2

如果有新版，會看到一行「This branch is X commits behind…」。按旁邊的 Sync fork，再按綠色的 Update branch。

3

GitHub 會在 1～3 分鐘內自動重新部署（Actions 分頁會出現新的一筆，等它變綠色勾勾）。之後把手機上的 Mothership 完全關掉再打開，就是新版了。右上角 設定 › 最下面會顯示版本時間。

4

保險起見，每次更新後把第 5 步的 SQL 再跑一次（用了 Beamup 的話，第 10 步的也跑一次）。這些 SQL 可以重複執行，不會動到你的資料；新版如果改了資料庫規則，這樣就會補上。

你的資料不會受影響更新的只是 App 本身，看板資料存在你的 Supabase 裡，不會被覆蓋。
Supabase 免費專案太久沒用會暫停如果大約一週都沒有人打開你的 Mothership，Supabase 會把專案暫停並寄信通知你。到 Supabase 後台按 Restore 就會恢復，資料都還在。平常有在用就不會發生。

卡住了怎麼辦

打開網址出現「404 There isn't a GitHub Pages site here」

網站還沒部署成功。檢查：第 3-2 步的 Source 是不是 GitHub Actions；第 8 步的 Actions 有沒有出現綠色勾勾。剛部署完也可能要再等一兩分鐘。網址最後的 /program_manager/ 也要打對。

Actions 裡看不到「Deploy to GitHub Pages」或沒有 Run workflow 按鈕

第 3-1 步還沒做：到 Actions 分頁按 I understand my workflows, go ahead and enable them。

Actions 出現紅色叉叉 ❌

點進那一筆看哪一步失敗。如果是 deploy 那步、訊息提到 Pages，通常是第 3-2 步的 Source 沒選 GitHub Actions，選好後按右上角 Re-run jobs。其他情況可以截圖問 Claude（見最下面）。

另一個叫 Deploy calendar function 的項目是行事曆同步用的，沒設定時會自動略過，不用管它。

註冊或登入時說「Email not confirmed」，或一直收不到確認信

照第 6 步的 2 把 Confirm email 關掉，再登入一次。已經註冊過的帳號也可以直接登入。

登入後顯示「暫時無法連線到雲端」或資料存不起來

多半是第 5 步的 SQL 沒有成功執行。回到 SQL Editor 再跑一次，看到 Success 為止。也確認第 7 步填的是你自己專案的網址和 key。

Supabase 的 Users 裡看不到我註冊的帳號

網站還接在原作者的資料庫：回到第 7 步檢查兩個 Variable（名稱完全一樣、放在 Variables 分頁），然後重做第 8 步的 1～3，重新部署一次。

點 Email 連結後跑到奇怪的網址，或顯示錯誤

第 6 步的 Site URL 和 Redirect URLs 要填你自己的網址，結尾的 /program_manager/ 也要有。

手機上看不到新功能

把 Mothership 從背景完全關掉（從螢幕下方往上滑，把它滑掉），再打開一兩次。右上角 設定 › 最下面會顯示版本時間。
